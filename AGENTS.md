# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, and any tool that reads `AGENTS.md`) when working with code in this repository.

## What this is

The `ai` CLI — the single control-plane binary for the **AI Development Platform**: reproducible, isolated AI dev environments where workspaces are hardware-isolated **Microsandbox microVMs**. The model path runs agent → host **Headroom** input-compression proxy → **LiteLLM** routing (with always-on **Presidio** secret-masking guardrails on every request) → containerized **Ollama** or a cloud provider; Headroom, Ollama, Presidio, and LiteLLM are all shared host containers (Headroom is no longer installed inside the workspace image). **Caveman** remains the per-project in-workspace output-compression skill. Credentials are **keys-in-LiteLLM**: real provider API keys live in the LiteLLM gateway (env passthrough at launch / its Postgres-backed store), never on platform disk or in the workspace — the agent holds only a scoped LiteLLM **virtual key**. Workspace egress is a **default-deny Microsandbox NetworkPolicy** configured per-project via `ai network` and applied as `msb` net-rules at workspace create; attempted egress is audited by domain name via the `aip-dns` resolver (`ai network log`). Secret/credential masking is LiteLLM's always-on guardrails — Presidio scoped to financial/identity secrets plus the in-process `hide-secrets` detector — which cloud routes cannot bypass. Go 1.26, one static binary, module `github.com/jt-helsinki/ideal-robot`.

**`spec/` is the source of truth, not documentation.** The six numbered specs define the end-state architecture (`01`), delivery slices (`02`), on-disk/repo layout (`03`), the exact CLI surface + JSON envelope + exit codes (`04`), acceptance tests (`05`), and the milestone build plan (`06`). Code comments cite spec sections (e.g. `§17`, `CLI §3.1`, `repo-layout §12.5`) — when changing behavior, read the cited section first and keep code and spec in sync. The build proceeds in milestones **M0–M8** (see `spec/06`), with later work organized as slices **S1–S6** (`spec/02`). The full surface is implemented (M0–M8 plus slices S1, S2, S4–S6; S3 and S7 retired) — host-side **and**, on a provisioned Apple Silicon host, the live external-tool integration: `ai setup` launches the service-tier containers (DNS audit resolver, Ollama, Presidio, LiteLLM + its DB, Headroom); LiteLLM mints scoped agent virtual keys and holds provider keys; workspace microVMs build, boot, and exec; the per-project `ai network` egress policy is applied as Microsandbox net-rules at workspace create; and the DNS egress audit (`ai network log`) works — all verified end-to-end this cycle. The narrow seams that still depend on further bring-up (live service/microVM log capture, the live Ollama health probe) are grep-able (`hardware bring-up`) and tracked in `docs/HARDWARE-BRINGUP.md`. Before changing a slice, read its milestone in `spec/06` and its `[Sx]`-tagged tests in `spec/05`.

## Commands

```bash
make build            # -> bin/ai  (injects version via -ldflags)
make test             # unit tests (go test ./...)
make fmt              # gofmt -w .
make fmt-check        # CI gate: fails if not gofmt-clean
make vet              # go vet
make lint             # golangci-lint (no-op if not installed; CI installs it)
make test-acceptance  # [S1] acceptance suite — STUB; needs Apple Silicon + Docker + Microsandbox
make tidy             # go mod tidy

go test ./internal/setup/ -run TestRunIdempotent   # a single test
go run ./cmd/ai --version --json                   # run without building
```

CI (`.github/workflows/ci.yml`) is split: hosted runners do build/vet/lint/unit-tests; a self-hosted **Apple Silicon** runner runs `[S1]` acceptance (the only host that can run the full stack). Before committing, `make fmt-check vet test build` should all pass — `errcheck` (via golangci-lint) is strict, so explicitly discard intentional writes (`_, _ = fmt.Fprintln(...)`).

## Architecture (the parts that span files)

**Output envelope is the universal contract.** Every command returns the `internal/output` envelope (`{ok, command, data, error, warnings}`, CLI §19). `error.code` **equals** the process exit code (§18: 0 ok, 2 invalid input, 3 missing dependency, 4 runtime failure, 5 permission). Pattern: `Execute()` (in `internal/cli/root.go`) owns an `exitCode` int and an `Emitter`; each cobra command's `RunE` does its work and sets `*exit = emitter.Success(...)` or `emitter.Failure(...)`, returning `nil`. Errors that must carry a specific exit code are `*output.Error` (build with `output.Errorf(code, ...)`); the emitter unwraps them. cobra/arg errors are mapped to exit 2 in `Execute`. Output is **human-readable by default**; the JSON envelope is emitted only with `--json` (commands provide a typed result + a Human renderer — see `ai logs`).

**External tools sit behind injectable interfaces; logic is faked in tests.** Docker/Podman, the Microsandbox runtime (`msb`), Ollama, and LiteLLM are never called directly from orchestration code. Instead: `runtime.Prober`, `setup.Services`, `secrets.Broker`, `litellm.Client`, `ollama.Client`. Orchestrators (`internal/setup`, etc.) take these via a `Deps`-style struct and are unit-tested with fakes; real implementations live in `*_real.go` and are wired by the CLI. Most of these real impls are now wired and verified on Apple Silicon — the service-tier container launches, LiteLLM key minting + provider-credential storage (`litellm.KeyManager`, `secrets.Broker` → LiteLLM `/credentials`), the workspace OCI build + `msb` microVM lifecycle (`workspace.Builder`/`Sandbox`), and the `ai network` egress policy applied as `msb` net-rules. **The few genuinely-unwired seams are commented `hardware bring-up`** (live service/microVM log capture, the live Ollama health probe); the lone `ErrPending` (`internal/workspace`) is vestigial. **Do not invent the external tools' CLI/API invocations** — verify against the real tool's docs (msb/CoreDNS/Presidio commands and the LiteLLM/Ollama HTTP APIs were verified empirically) or leave the seam and mark it deferred.

**Newer packages worth knowing.** `internal/ollama` (required local-model service, run as the `aip-ollama` container), `internal/contextopt` (Headroom strategy + Caveman level, per-project, surfaced by `ai context`; the strategy maps to Headroom's per-request `keep_turns`/`output_buffer_tokens` body knobs baked into the agent's `extra_body` at workspace start — `HeadroomParams`), `internal/overlay` (S4 per-workspace persistence), `internal/envimage` (workspace OCI image build from the project Dockerfile), `internal/console` (admin-dashboard URL registry for `ai services console`), `internal/templates` (embedded OS/stack/agent-CLI snippets), `internal/uninstall` (native `ai uninstall` teardown), `internal/egress` (per-project workspace egress policy — mode + allow-list + published ports, surfaced by `ai network`; `MsbNetworkArgs` renders it into `msb` net-rules), `internal/agentcfg` (the in-VM agent provider config written at workspace start — base_url → host Headroom `:18787`, the scoped virtual key, and the project's `HeadroomParams` as request `extra_body`), `internal/litellm` (also the `KeyManager` virtual-key client), `internal/layout`. The `aip-dns` CoreDNS resolver is the egress-audit backend (`ai network log`): microVMs boot with `--dns-nameserver` pointed at it, so every queried name is logged. **Version control is out of scope** — there is no git package and `ai project create` runs no git. **Supported hosts are macOS (Apple Silicon) and Linux** — there is no cross-OS path-translation layer.

**State is split global vs project-local, written atomically.** Global lives under `~/.ai-platform/` (config, `runtime.json`, `versions.json`, `projects.json` index); per-project state lives in `<project>/.ai-platform/` (tracked `Dockerfile`/`config.yaml`/`profile.yaml`/`project.json`/`skills/caveman/`, gitignored `run/`). All paths derive from `os.UserHomeDir()` via `internal/paths`, so **tests redirect with `t.Setenv("HOME", t.TempDir())`**. All JSON writes go through `internal/jsonfile` (temp file + `rename`; reads reject unknown fields). Config merges `project > global` via `internal/config` (deep map-merge).

**Dual runtime model.** Microsandbox microVMs run workspaces; Docker/Podman run the service tier on the shared `aip-net` network, reconciled in order network → DNS → Ollama → Presidio → LiteLLM(+DB) → Headroom → Open WebUI: `aip-dns` (CoreDNS egress-audit resolver, bound to host loopback `127.0.0.1:15353/udp`; microVMs use it via `--dns-nameserver`), `aip-ollama` (required local models, reached by name at `http://aip-ollama:11434`; models persist on the host at `~/.ai-platform/models`), the `aip-presidio-analyzer`/`aip-presidio-anonymizer` pair backing LiteLLM's always-on secret-masking guardrail, `aip-litellm` (the gateway, host-published :14000 → container :4000) plus a small `aip-litellm-db` Postgres (trust auth, host port 5442 loopback) that backs LiteLLM's DB-backed admin UI/virtual keys + the encrypted provider-credential store (the one stateful service-tier piece), and `aip-headroom` (the input-compression proxy in front of LiteLLM, `OPENAI_TARGET_API_URL=http://aip-litellm:4000`, `HEADROOM_NO_CCR_INJECT_TOOL=1`; pulled image, never built), and the optional `aip-open-webui` (the chat UI, published on the host at :18090, routed through LiteLLM as an OpenAI-compatible gateway via `OPENAI_API_BASE_URL=http://aip-litellm:4000/v1` with `ENABLE_OLLAMA_API=false`/`WEBUI_AUTH=false`; the LiteLLM master key, when set, is passed via env passthrough as `OPENAI_API_KEY`). There is no native firewall service; provider credentials live in LiteLLM (keys-in-LiteLLM). Detection (`internal/runtime` + `internal/sandbox`) is parameterized by `GOOS/GOARCH` + a `Prober` so it tests on any host; missing deps → exit 3, missing rootless/virtualization → exit 4. macOS requires **Apple Silicon** (no Intel). Per-project workspace egress is declared via `ai network` (modes deny[default]/public/unrestricted, allowed host services incl. domains + `*.suffix`, published ports, stored in `config.yaml`) and applied as default-deny Microsandbox net-rules (`egress.MsbNetworkArgs`) at workspace create.

**Model catalogue is global and agent-selected.** LiteLLM (the shared host gateway) exposes models via per-provider **wildcards** (`ollama/*`, `openai/*`, `anthropic/*`, `gemini/*`, `groq/*`) plus a few named handles (aliases `gpt-5.5`/`claude-opus`/`gemini-pro`); the default model is the local Ollama `gemma4` (→ `ollama/gemma4:31b`, `litellm.DefaultRouting` in `internal/litellm`). The in-workspace agent names any model per request and LiteLLM routes it (real provider keys live in LiteLLM; the agent authenticates to the gateway with a scoped virtual key, Ollama needs none) — there is **no per-project model config**. LiteLLM's generated config renders **always-on guardrails** (all `default_on: true`), scoped to **secrets/credentials, not general PII**: `presidio-secrets-input` (pre_call) + `presidio-secrets-output` (post_call) mask only financial/identity secrets (CREDIT_CARD, US_SSN, US_BANK_NUMBER, IBAN_CODE, CRYPTO — see `secretEntities`), plus `hide-secrets` (LiteLLM's in-process detect-secrets) for API keys/tokens. Masking general PII (names, places, emails) was deliberately removed — it corrupted ordinary coding prompts. Because default-on guardrails run on every request and all routes (cloud included) traverse the proxy, cloud calls cannot bypass them. Registering a model ≠ installing it (an Ollama model still needs `ollama pull`; a cloud model still needs its key). `ai services start|stop|restart` manage the whole platform container set (ollama, presidio, litellm, headroom, open-webui, dns); ClawPatrol is gone and there is no native service to manage. The LiteLLM admin UI is secured with `UI_USERNAME`/`UI_PASSWORD`/`LITELLM_MASTER_KEY` passed by **env passthrough** (values never in argv/config/disk); `ai setup` prompts for the password on a TTY.

**`ai project create` is an interactive PTY wizard** (CLI §3.1), built on `charmbracelet/huh`: no `--os` or per-choice flags — project name, OS (`debian-trixie`/`debian-bookworm`/`ubuntu`/`alma`), agent CLIs (multi-select: `opencode`/`pi`/`claude-code`/`codex`/`gemini` — `opencode` (default tool) and `pi` are installed by default, both wired to LiteLLM), and software stacks (`go`/`node`/`python`/`rust`/`java`/`maven`/`deno`) are picked in menus. The project is created **in the current directory** (no fixed `~/projects`); if the cwd is already a project it **attaches** instead. The platform runs **no git** (VCS is out of scope). No TTY → exit 2; `--dry-run` emits the side-effect-free action plan. Automation drives it through a pseudo-terminal (`creack/pty`; acceptance harness in `test/acceptance`, §1.4).

## Conventions

- **No single-character variable names anywhere** — including method receivers and loop vars (`store`, `emitter`, `prober`, `entry`, `value`, …). Self-documenting names over Go's terse-receiver convention. The one kept exception is the test handle `t *testing.T`.
- **Secrets never touch platform disk.** Values flow straight to the LiteLLM credential store via `secrets.Broker` (`internal/secrets`, which `ai secrets` fronts); `secrets.Entry` has no value field by design, so listings can't leak.
- Commit messages must not include AI-attribution trailers (no `Co-Authored-By` for the assistant). Commit only when asked; the work lives on a feature branch off `main`.
